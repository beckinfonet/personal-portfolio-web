<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> Vercel insights endpoint | `<Analytics />` and `track()` send page-view + custom-event beacons to `/_vercel/insights/*`. Beacon payload is minimal (event name + page path + anonymized client signals; NO PII per D-11 bare-payload rule). |
| `track("resume_download")` invocation site | Client-component event handler; runs only in the browser. No server-side execution. |
| Third-party dependency `@vercel/analytics@^2.0.1` | New prod dep — supply-chain exposure surface. Mitigated by `npm audit` gate (Plan 06) and version pinning to ^2.0.x (no auto-major upgrades). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-09 | Information Disclosure | `track("resume_download")` event payload | mitigate | D-11 enforces bare payload — `track()` is called with no second-arg props. No viewport, theme, accent, IP, user-agent, or PII shipped. The beacon contains only event name + Vercel-set anonymized session signals. |
| T-07-10 | Tampering | `@vercel/analytics` package supply chain | mitigate | Version pinned to `^2.0.1` (no auto-major); lockfile committed; Plan 06 runs `npm audit --omit=dev --audit-level=high` as close-out gate to catch newly-disclosed CVEs in this dep. |
| T-07-11 | Denial of Service | Beacon transport from client | accept | SDK uses `navigator.sendBeacon` with `fetch keepalive` fallback. Both are bounded by browser (sendBeacon 64KB cap, single attempt). Cannot be weaponized against the server. |
| T-07-12 | Repudiation | Analytics dashboard count vs actual click count | accept | Vercel dashboard count can differ from actual clicks due to ad-blockers, DNT, beacon delivery failures. Not a security concern — this is metric-fidelity, not auth. Documented in Pitfall 3 RESEARCH.md. |
| T-07-13 | Spoofing | Client-fired `track()` calls | accept | Any client can call `track("resume_download")` from devtools console on the production page (or via any fetch to `/_vercel/insights/event`). This is a metric-pollution risk only — no security impact. Vercel rate-limits server-side. |
| T-07-14 | Elevation of Privilege | `<Analytics />` injected into RSC root | mitigate | The component is a thin client component (package-internal `"use client"`); it does NOT escalate parent to client. RSC discipline preserved. Task 3's verify includes `! grep -q '"use client"' app/layout.tsx`. |
