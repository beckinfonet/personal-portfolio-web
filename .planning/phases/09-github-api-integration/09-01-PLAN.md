The GitHubRepoStats shape is LOCKED by GH-07 / RESEARCH Pattern 5. Define it in
lib/types.ts near the Project interface:

  interface GitHubRepoStats {
    createdAt: string        // earliest created_at across all repos (ISO 8601)
    pushedAt: string         // latest pushed_at across all repos (ISO 8601)
    languages: Record<string, number>   // merged byte map, bytes summed per key
    commitCount: number      // summed commit count across all repos
  }

The public surface of lib/github.ts is LOCKED by GH-01 / D-domain:

  export async function getRepoStats(repoUrls: string[]): Promise<GitHubRepoStats | null>

The lib/api.ts ISR-fetch + silent-fallback shape this module adapts:

  async function getJson<T>(path, fallback) {
    try {
      const response = await fetch(url, { next: { revalidate: 300 } });
      if (!response.ok) return fallback;
      return (await response.json()) as T;
    } catch { return fallback; }
  }

lib/github.ts uses revalidate: 86400 (not 300) and returns null (not a typed
fallback constant) on failure.

Internal helper decomposition (Claude's Discretion per CONTEXT D-domain — the
RESEARCH System Architecture Diagram recommends this cut, use it):
  - parseRepoUrl(raw) / parseRepoUrls(repoUrls)  — URL parse + host allow-list + dedupe
  - ghHeaders()                                  — conditional bearer-auth headers
  - fetchRepoStats(owner, repo)                  — per-repo 3-endpoint fetch → RepoStat | null
  - commitCountFromLink(linkHeader, arrayLength) — Link-header rel=last parser
  - combineStats(results)                        — sum/merge/min/max reduce
  - readDiskCache() / writeDiskCacheEntry(key, stat) — failure-tolerant disk I/O
