  <what-built>
    Nothing automatable — GSC has no API access surface in scope; DNS panel is in Vercel UI. Two external systems to coordinate.
  </what-built>
  <how-to-verify>
    1. Open https://search.google.com/search-console in a browser logged into the Google account that will own this property (treat as a permanent ownership decision — Google account changes are painful later).

    2. Click "Add property". Choose the **Domain** option (left card; NOT URL prefix). Enter `tatibekov.com` (apex; no `www.`; no `https://`).

    3. GSC generates a TXT record string like `google-site-verification=AbCdEf1234567890_some_long_token`. Copy the full string.

    4. Open Vercel Dashboard -> Domains -> click `tatibekov.com` -> DNS tab. Click "Add Record".
       - Type: `TXT`
       - Name: `@` (root — the apex, NOT `www`)
       - Value: paste the full `google-site-verification=...` string
       - TTL: 60 (or default; doesn't matter much)
       - Save.

    5. Wait 1-5 minutes for DNS propagation (Vercel DNS is usually fast; can take "a day or two" per Google's docs for slow registrars, but Vercel DNS typically propagates within minutes).

    6. Return to GSC and click "Verify" on the property setup screen.

    7. GSC should report "Ownership verified". Screenshot this confirmation screen (or the property's overview page showing the green "Verified" badge) to `.planning/phases/07-deploy-verification/gsc/verification.png`.

    CRITICAL constraints:
    - Do NOT delete the TXT record after verification — Google re-checks it periodically and will un-verify the property if it's missing (Pitfall 6).
    - Do NOT add the TXT record to `www.tatibekov.com` (sub-domain); it MUST go on the apex `tatibekov.com` for a Domain property.
    - Do NOT use an existing GSC property if one was created for a previous version of the site (URL property at `https://www.tatibekov.com/`) — Domain property is the new canonical property per D-06. You can delete the old URL property after Domain verification succeeds.
  </how-to-verify>

| TXT record persistence | Must remain in DNS forever; deletion un-verifies the property. |

| T-07-19 | Information Disclosure | TXT record reveals "this domain uses GSC" | accept | Universal pattern; any domain on Google's index has a verification record. No competitive intel leak. |
| T-07-20 | Spoofing | Sitemap submission of an attacker-controlled URL | mitigate | Submission is gated by GSC property ownership; only verified owners can submit. Verified by Task 1 DNS TXT + Google's verification check. |
| T-07-21 | Repudiation | Indexing-status snapshot vs future state | accept | Per Pitfall 2, indexing is async; the snapshot represents a point-in-time. Documented inline (capture date in Task 4 section). |

ASVS L1: PASS. Read-only external integration; no auth surface, no PII, no secrets.
