<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| seed/fallback content -> rendered DOM | `repoUrls` strings are committed content; Phase 10 may render them as hrefs |
| `repoUrls` strings -> Phase 9 `lib/github.ts` fetch | URLs become fetch targets for the GitHub API integration |
| MongoDB document -> `/api/projects` response | Mongoose strict-mode governs which fields persist/serialize |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-01 | Tampering | `repoUrls` values in seed/fallback | accept | All 4 projects' `repoUrls` are author-controlled, committed-to-git, code-reviewed HTTPS GitHub URLs from the D-04 table — not user input. No runtime injection surface in Phase 8 (no endpoint accepts `repoUrls`). |
| T-08-02 | Information disclosure | non-HTTPS or non-GitHub URL leaking into `repoUrls` | mitigate | Both the backend Jest spec and the frontend vitest assert every present `repoUrls` element matches `/^https?:\/\//`. INFRA-05 prebuild grep additionally blocks placeholder/forbidden strings from reaching a production build. |
| T-08-03 | Elevation of privilege | extra/unknown field bypassing Mongoose `strict` mode | mitigate | The `Project` schema retains `strict: 'throw'` unchanged; `repoUrls` is added as a declared optional `[String]` field, so it is a known field — no strict-mode bypass. The Jest `/api/projects` spec confirms no `_id`/`__v` leakage persists alongside the new field. |
| T-08-04 | Tampering | private/unreachable repo URL in `repoUrls` | accept | Per D-06, private/unreachable repos are simply skipped by Phase 9 (GitHub returns 404 to the public read-only token); graceful degradation is the v1.1 design intent. Phase 8 introduces no fetch, so there is no live exposure here. |

No `high`-severity threats — Phase 8 adds an optional, additive, author-controlled
string-array field with no new endpoint and no runtime input surface. Proceed.
</threat_model>
