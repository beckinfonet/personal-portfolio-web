<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Build-time metadata composition | Next.js processes `metadata` and `viewport` exports at build time and emits `<meta>` tags into `<head>`. A typo in `viewport.themeColor` color value (non-hex string) would emit malformed metadata; a typo in `media` query would silently mis-match all schemes. |
| Reduced-motion `!important` precedence | The universal-selector reset uses `!important` on 3 properties, overriding ALL author-defined animations. A future Phase 6/7 animation that intentionally bypasses reduced-motion would have to use `animation-duration: ... !important` itself or explicitly opt out. This is the documented behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-10 | Tampering | Deprecated metadata.themeColor location | mitigate | Acceptance criteria explicitly checks `! grep -q 'metadata.themeColor' app/layout.tsx` AND `npm run build` log MUST NOT contain `themeColor in metadata is deprecated`. The vitest assertion `expect(metadata.themeColor).toBeUndefined()` belt-and-suspenders the same. |
| T-05-11 | Denial of Service | `0ms` reduced-motion silent failure | mitigate | Acceptance criteria checks `! grep -q 'animation-duration: 0ms' app/globals.css` and `grep -q 'animation-duration: 0\.01ms !important'`. Pitfall 7 — `0ms` would silently fail in some browsers, leaving vestibular-trigger users with full-speed animations. |
| T-05-12 | Tampering | Duplicate @media (prefers-reduced-motion: reduce) blocks | mitigate | Acceptance criteria checks `grep -c '@media (prefers-reduced-motion: reduce)' app/globals.css` returns exactly `1`. Multiple matching media queries would produce duplicate rules and unpredictable cascade order. |
</threat_model>
