Final file:

```yaml
name: CI

on:
  pull_request:
    branches: [main]

# Cancel in-flight runs of the same PR when new commits push (saves CI minutes)
concurrency:
  group: ci-${{ github.event.pull_request.number }}
  cancel-in-progress: true

jobs:
  verify:
    runs-on: ubuntu-latest
    timeout-minutes: 10

    steps:
      - name: Checkout
        uses: actions/checkout@v4
        with:
          fetch-depth: 1

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version-file: .nvmrc
          cache: npm

      - name: Install dependencies (lockfile-strict)
        run: npm ci

      - name: Lint
        run: npm run lint

      - name: Typecheck
        run: npm run typecheck

      - name: Test
        run: npm test

      - name: Knip — fail on orphan files / unused exports
        run: npx knip

      - name: Build
        run: npm run build
        env:
          # Provide a stable site URL so metadataBase resolves cleanly during build
          NEXT_PUBLIC_SITE_URL: https://example.com
          # Backend is not required during CI build — getJson silently falls back
          NEXT_PUBLIC_API_BASE_URL: ""
```

YAML conventions:
- 2-space indent (matches project TS/JSON convention)
- Double quotes only when needed (YAML idiomatic)
- Job name `verify` — matches the status-check selector in branch protection (D-06)

Note on the Build step: it runs `npm run build` (NOT `next build`) so the `postbuild` chain from Plan 05 executes. <threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local developer machine ↔ committed source | CI is the gate that checks committed source against the lint/typecheck/test/knip/build pipeline before allowing merge to `main`. |
| `main` branch ↔ production deploy (Vercel) | Vercel deploys from `main` automatically; CI green is the only software guard between PR merge and prod. |
| External package registry (npm) ↔ CI install | `npm ci` enforces lockfile match; out-of-sync lockfile fails install (catches the lockfile-drift class of supply-chain regressions). |
