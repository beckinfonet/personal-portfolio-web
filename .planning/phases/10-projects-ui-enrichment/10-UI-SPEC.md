# Phase 10 — UI Design Contract

> Visual and interaction contract for the `/projects` stat strip + Tech highlights panel. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — established codebase, styling approach locked by CLAUDE.md |
| Preset | not applicable |
| Component library | none — pure CSS + CSS custom properties (no Tailwind, no CSS-in-JS, no CSS modules) |
| Icon library | none — terminal/IDE aesthetic uses monospace text tokens, not SVG icons (D-11: `gh:` is a text token, not an octocat SVG) |
| Font | JetBrains Mono (`--font-mono`, loaded via `next/font/google` in `app/layout.tsx`) |

**Note:** shadcn initialization gate skipped. This is a brownfield Next.js 15 codebase mid-redesign; CLAUDE.md explicitly forbids Tailwind / CSS-in-JS / CSS modules and caps prod deps at three (`next-themes`, `cmdk`, `@vercel/analytics`). No new design-system tooling is permitted in this phase. All Phase 10 styling extends the existing `.projects-*` block in `app/globals.css` (LIST-08, D-10).

## Spacing Scale

Project uses an existing ad-hoc scale in `app/globals.css` (not a strict 8-point grid — predates this phase). Phase 10 reuses these existing values; it does NOT introduce a new scale.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Strip inner gaps; `.projects-row-summary` top-margin precedent |
| sm | 8px | `.projects-row-chips` top-margin; strip top-margin below the chip row |
| md | 16px | `.projects-row` grid `gap`; `.projects-row` vertical `padding`; panel internal padding |
| lg | 24px | Tech highlights panel section breaks |
| — | 14px | `.projects-subhead` bottom-margin (existing — preserved) |

Exceptions: The codebase already uses 14px and other non-8-multiple values in the `.projects-*` block. Phase 10 MUST reuse existing `.projects-*` tokens and spacing rather than re-grid the row (LIST-08 + D-10 are binding: "no new top-level CSS section", "3-column grid `32px / 1fr / 110px` untouched"). The 8-point grid is a guideline; matching the existing surrounding block takes precedence here.

## Typography

All sizes reuse the existing `.projects-*` scale. JetBrains Mono is the only font; weights are constrained to two: regular (400) and semibold (600) — matching the existing `.projects-row-name` (600) vs body (400) split.

| Role | Size | Weight | Line Height | Element |
|------|------|--------|-------------|---------|
| Row name | 15px | 600 | 1.2 | `.projects-row-name` (existing — unchanged) |
| Body / summary | 13px | 400 | 1.5 | `.projects-row-summary`, panel body text (existing pattern) |
| Stat strip | 12px | 400 | 1.5 | New `.projects-row-stats` — matches `.projects-row-index` 12px muted scale |
| Meta / label | 11px | 400 | 1.4 | `.projects-row-year/status/role` (existing); panel sub-labels |
| Panel commit-count stat | 15px | 600 | 1.2 | Prominent commit number (DETAIL-05) — reuses the row-name 15px/600 emphasis tier |

Rule: no new font sizes beyond the five tiers above (15 / 13 / 12 / 11). The strip sits at the 12px tier so it reads as secondary metadata, subordinate to the 13px summary and 15px name.

## Color

The `/projects` view inherits the global token system in `app/globals.css` (`:root` dark + `[data-theme="light"]`, 4 swappable accent hues via `--accent-hue`). No new color tokens are introduced.

| Role | Token | Usage in this phase |
|------|-------|---------------------|
| Dominant (60%) | `--bg` (#0a0c0b dark / #f4f2ea light) | Page background, collapsed row background |
| Secondary (30%) | `--panel` (#0d100f dark / #ffffff light) | Row hover background; expanded Tech highlights panel surface |
| Accent (10%) | `--accent` (oklch, hue-swappable) | See reserved list below |
| Semantic — warn | `--warn` | `.projects-row-status` only (existing — unchanged) |

Accent reserved for:
- The `gh:` source-marker token on the stat strip (D-11 — themeable across 4 hues × 2 themes)
- The "View on GitHub →" CTA link text (DETAIL-06 — inherits `a { color: var(--accent) }`)
- The "Visit project" CTA link text (the moved `project.link`)
- The project row name `.projects-row-name` (existing — unchanged)
- The prominent commit-count number in the Tech highlights panel (DETAIL-05)

Strip body text (commit count, language list, duration — excluding the `gh:` token) uses `--muted` / `--muted-hi`, NOT accent. The strip must read as quiet metadata. Accent is the source-marker and the actionable links only — never the whole strip.

Language byte-breakdown bars/percentages in the panel (DETAIL-02): use `--muted-hi` for the percentage figures and `--border-hi` / `--accent-bg` for any bar fill. No new semantic color.

Destructive: not applicable — Phase 10 has zero destructive actions (read-only stat display).

Contrast obligation: every new strip and panel selector must pass WCAG 2.1 AA color-contrast under all 4 accent hues × 2 themes (DETAIL-08). New selectors are added to the existing v1.0 Phase 5 56-cell axe matrix (`tests/contrast.spec.ts`). `--muted` at 12px on `--bg` is the known tight pair — verify the strip explicitly.

## Copywriting Contract

All copy is pre-specified by REQUIREMENTS.md (LIST-02..05, DETAIL-03..06) and CONTEXT.md. Verbatim formats below are binding.

| Element | Copy |
|---------|------|
| Stat strip format | `gh: <commits> commits · <lang1>[ / <lang2>][ / <lang3>] · <duration>` — e.g. `gh: 247 commits · TS / CSS · 4mo` (LIST-02, LIST-05, D-11) |
| Strip source marker | Literal monospace text token `gh:` (D-11 — not an octocat SVG) |
| Strip language list | Top 3 languages by byte count, dropping any under 1% of total (D-08); abbreviated via curated map, `TypeScript→TS` / `JavaScript→JS` etc. (D-06); languages absent from the map render their full GitHub name verbatim (D-06) |
| Strip duration | Months under a year (`4mo`); years + months above (`1y 2mo`) — computed `created_at`→today (LIST-04) |
| Detail panel heading | `Tech highlights` (DETAIL-01) |
| Panel language breakdown | Full GitHub language names + percentages, top 5 + `other` bucket (DETAIL-02, D-07, D-09) — e.g. `TypeScript 68%` |
| Panel duration line | `In development since Jan 2026 — 4mo` (DETAIL-03) |
| Panel last-active line | `Last active 3 days ago` / `Last active 2 months ago` (relative — DETAIL-04) |
| Panel commit stat | `<n> commits` rendered as a prominent stat (DETAIL-05) |
| Primary CTA (repo) | `View on GitHub →` — links to `repoUrls[0]`, via `ExternalLink` primitive, `target=_blank rel=noopener noreferrer` (DETAIL-06, SEO-05) |
| Secondary CTA (project) | `Visit project →` — the moved `project.link`, via `ExternalLink` primitive |
| Empty state (no projects) | `total 0 · (no projects committed yet)` — existing `.empty-state` copy, unchanged |
| "No stats" degraded state | NO copy — render nothing. A project with empty/absent `repoUrls` or null combined stats shows no strip and omits the Tech highlights block entirely. No placeholder, no "private" label, no "stats unavailable" text (LIST-07, DETAIL-07, D-03). |
| Error state | NO error UI surfaced — `getRepoStats()` never throws and returns `null` on failure (GH-06); `null` is rendered as the silent "no stats" state above. There is no user-facing error path in this phase. |
| Destructive confirmation | not applicable — no destructive actions |

## Interaction Contract

Phase 10's one architectural change: the project row stops being an external `<a>` and becomes an expand/collapse disclosure.

| Aspect | Contract |
|--------|----------|
| Trigger | The row body (`1fr` column) is the toggle control (D-02). Row click expands/collapses the panel. |
| Pattern | Disclosure / accordion-style inline expand — no `/projects/[slug]` route is created (D-01). The "detail page" is the expanded card state. |
| Multi-open | Independent toggles — each row opens/closes on its own; multiple panels may be open at once (D-04). NOT a single-open accordion. |
| Strip placement | Collapsed row carries the `gh:` stat strip inside the body `1fr` column, directly below `.projects-row-chips` (D-10). The 3-column grid `32px / 1fr / 110px` and the right meta column are untouched. |
| Links | All external links (`View on GitHub →`, `Visit project →`) live inside the expanded panel only — never in the collapsed row. This resolves the nested-anchor problem (D-02, D-05). |
| Expand cue | A visible affordance is REQUIRED on the collapsed row so the row reads as interactive. Recommendation: a monospace `[+]` / `[-]` toggle glyph in the `32px` index column (replacing or adjoining the `01.` index), color `--muted`, flipping to `[-]` when open. Rationale: matches the terminal/IDE aesthetic, needs no SVG, themeable. (CONTEXT lists this as a planner/UI-contract call — this spec resolves it: yes, show a cue, as a text glyph.) |
| Client boundary | The expand toggle + panel visibility is a NEW thin client island (`"use client"`). The collapsed strip is server-rendered. `getRepoStats()` runs in the RSC layer (`projects/page.tsx`); strip text + panel data are passed as props into the client island. The island never imports `lib/github.ts`. |
| Keyboard / a11y | Toggle is a real `<button>` with `aria-expanded` + `aria-controls` pointing at the panel. Panel has a stable `id`. Existing per-row `aria-label` intent is preserved (plain-noun, recruiter-legible). Must pass WCAG 2.1 AA (DETAIL-08). |
| Motion | Any expand/collapse transition must respect `prefers-reduced-motion` — the global `*` animation reset in `app/globals.css` (Phase 5) already covers this; do not add motion that bypasses it. A no-animation instant toggle is acceptable. |
| Mobile (480px) | Strip wraps via CSS `flex-wrap` — it does NOT truncate the language list (D-12). All 1-3 languages stay visible; the strip flows to a second line. No JS measurement, no truncation code path. No horizontal scroll on the card row at 480px (SC-3). |

**Requirement-wording deviation (D-13 — carry into the plan):** LIST-06 / LIST-09 / ROADMAP SC-3 / SC-5 reference a strip "truncation to top-1" branch. D-12 chooses pure-CSS `flex-wrap` instead, so there is no truncation code path. The Vitest for LIST-09 is retargeted to assert the strip's rendering/layout contract (all selected languages render; the container is wrap-enabled), NOT truncation logic. The plan-checker / verifier must not fail the phase for the absent truncation branch.
