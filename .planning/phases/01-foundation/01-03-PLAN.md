**CRITICAL OPERATOR CHOICE:** Use logical OR `||` for `siteUrl`, NOT nullish-coalescing `??`. The rest of the codebase (`lib/api.ts:10`, `app/sitemap.ts:4`, `app/robots.ts:4`) uses `??` — those files are CORRECT for their inputs (a missing env var → fallback URL string is fine). But `app/layout.tsx` `metadataBase` requires `||` because:

- `??` returns the right operand only when left is `null` or `undefined`
- `process.env.NEXT_PUBLIC_SITE_URL = ""` (empty string set in CI) is NOT nullish — `??` lets the empty string through
- `new URL("")` throws `TypeError: Invalid URL` → build crashes
- `||` returns the right operand on ANY falsy left value (including `""`)
- Plan 06's CI workflow sets `NEXT_PUBLIC_SITE_URL: https://example.com` (non-empty), but local dev / future Vercel runs may pass empty strings → defensive operator required

This is the ONLY file in the repo where `||` is the correct operator. Per PATTERNS.md "the planner must call this out explicitly so the executor doesn't pattern-match the wrong operator."

import "./globals.css";

const siteUrl = process.env.NEXT_PUBLIC_SITE_URL || "http://localhost:3000";

export const metadata: Metadata = {
  metadataBase: new URL(siteUrl),
  title: "Beck Maldin | Mobile & Full-Stack Engineer",

const themeScript = `
(() => {
  try {
    const stored = localStorage.getItem("portfolio-theme");

      document.documentElement.setAttribute("data-theme", stored);
    }
  } catch {}
})();
`;

export default function RootLayout({

      </body>
    </html>
  );
}
