<objective>
Eliminate the static-PROFILE bypass in the persistent shell so Mongo-managed profile changes flow through the existing lib/api.ts ISR + graceful-fallback contract to every surface that renders profile data. The shell currently imports the static `PROFILE` constant from `lib/portfolio-data.ts` in 6 components (top-bar, sidebar, console-signature, explorer-drawer, json-ld-person, plus palette-verbs feeding command-palette) plus the layout itself, which means MongoDB edits to profile fields NEVER reach the shell — they only reach the per-route page bodies that call `getJson` directly.

After this plan, `app/(terminal)/layout.tsx` becomes async, fetches the profile once via `getProfile()` at the top of the render, and passes the resulting `profile: Profile` object as a prop to each shell child that needs it. The static `PROFILE` export in `lib/portfolio-data.ts` STAYS — it is the fallback returned by `getJson<Profile>('/api/profile', PROFILE)` when the BE is unreachable. The api.ts contract is unchanged.

Purpose: DATA-04 (existing ISR + graceful-fallback pattern preserved). The current shell behavior violates DATA-04 in spirit because the shell bypasses the api.ts chokepoint that DATA-04 explicitly designates. After this plan, lib/api.ts is the single chokepoint for ALL profile reads in the shell AND in route bodies — Mongo edits propagate site-wide on the next ISR window.

Output: 8 files modified (1 layout + 5 shell client islands + 1 RSC json-ld + 1 lib palette-verbs); zero new dependencies; lib/api.ts unchanged; static PROFILE stays in lib/portfolio-data.ts as the fallback fixture.
</objective>
