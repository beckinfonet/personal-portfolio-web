<!-- RESEARCH §"Pattern 5: Express on Railway" + §"Pattern 6: Next.js NEXT_PUBLIC env var injection". -->

Current `portfolio-services/src/config/env.ts`:
```typescript
export const env = {
  port: Number(process.env.PORT ?? 4000),
  mongoUri: process.env.MONGO_URI ?? 'mongodb://localhost:27017/portfolio_services',
  nodeEnv: process.env.NODE_ENV ?? 'development'
};
```

Per RESEARCH Assumption A2: Railway Mongo plugin typically injects `MONGO_URL` (not `MONGO_URI`). The env.ts above reads `MONGO_URI`. Two mitigation paths:
- (a) Set a Railway reference variable: `MONGO_URI = ${{Mongo.MONGO_URL}}` in the Express service. Zero code change.
- (b) Edit env.ts to read both names with a fallback chain. One-line code change.

Default to (a) (dashboard config) because it requires no commit. If the Railway UI's reference-variable syntax fails or feels brittle at execution time, fall back to (b).

Vercel inlines `NEXT_PUBLIC_*` vars at build time (Pitfall 7). Setting the var without a redeploy is a no-op. After setting:
- Push any commit OR click "Redeploy" in the Vercel dashboard.
- Vercel rebuilds; the new value is baked into the server bundle.
