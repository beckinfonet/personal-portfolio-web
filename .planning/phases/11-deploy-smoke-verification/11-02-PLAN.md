<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner shell -> GitHub API | The `GITHUB_TOKEN` lives in the owner's shell env for the curl probes — never echoed into a committed file |
| Vercel Production env -> public site | The token is read server-side at build/ISR time; `lib/github.ts` is server-only and never reaches the client bundle |
| verification document | `11-SMOKE-VERIFICATION.md` is committed and public — it records observed numbers and key names, never the token value |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-04 | Information disclosure | `GITHUB_TOKEN` value pasted into `11-SMOKE-VERIFICATION.md` | mitigate | Every task records only key names (`vercel env ls`), observed stat values, and rate-limit numbers; acceptance criteria explicitly forbid the token value; curl commands use `$GITHUB_TOKEN` shell-env reference, never an inline literal |
| T-11-05 | Information disclosure | Token leaked via deploy logs / terminal scrollback | mitigate | Owner runs curl probes with the token in shell env; only the numeric `remaining` output is copied back — not the command's auth header |
| T-11-06 | Spoofing / tampering | A private repo's metadata exposed on the public site | accept | D-01 scopes the PAT to public-repo metadata only; private repos correctly degrade to no-strip (LIST-07 / DETAIL-07) — no private metadata is reachable |
</threat_model>
