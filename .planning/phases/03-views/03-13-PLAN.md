    ```js
      /lorem/i,

    ```

    **Update the comment block** (lines 6–11) to document the intent:

    ```js
    // Forbidden strings:
    //   lorem                              (case-insensitive)
    //   example.com                        (case-insensitive)
    //   placeholder + (text|content|string|image|name)  (case-insensitive — phrase-based to avoid the
    //                                       legitimate HTML "placeholder" attribute)
    //   TODO                               (CASE-SENSITIVE — D-10 grammar; lowercase "todo" in prose passes)
    //   Product Studio                     (CASE-SENSITIVE — exact demo company name leak from CONCERNS.md)
    ```

    **Why phrase-based for `placeholder`:** the standalone word `placeholder` is a legitimate HTML attribute on `<input>`, `<textarea>`, and component libraries (cmdk, MUI, etc.). The word's appearance in compiled JS is not a content-leak signal. Real placeholder content always appears as a phrase: "placeholder text", "placeholder image", "placeholder string", "placeholder name", or "placeholder content". The 5-keyword phrase regex catches all common placeholder content patterns without false-positiving on the legitimate attribute name.

    **DO NOT** remove the `/placeholder .../i` regex entirely (the gate must still fail on actual placeholder content). DO NOT change any other regex.
  </action>
